# グローバルメモリ

## 言語

出力は日本語で行うこと。

## 開発スタイル

- TDD で開発する（探索 → Red → Green → Refactoring）。
- KPI やカバレッジ目標が与えられたら、達成するまで試行する。
- 不明瞭な指示は質問して明確にする。

## コード設計

- 関心の分離を保つ
- 状態とロジックを分離する
- 可読性と保守性を重視する
- コントラクト層（API/型）を厳密に定義し、実装層は再生成可能に保つ

## 設計時の方針

開発における設計提案（アーキテクチャ、モジュール構成、命名規則、API設計など）を行う際は、事前知識のみに頼らず、必ず Web 検索で業界標準・最新のベストプラクティスを確認した上で提案すること。

## 事実確認

- 「未確認」「〜と記憶している」のまま回答しない。確かめられること（ソースコード、公式ドキュメント、Web 検索、実行結果など）は、確認してから答える。
- 手段を尽くしても確認できなかった場合に限り、そう明記する。何を試し、なぜ確認できなかったかも添える。

## ドキュメンテーションの書き分け

- コードには How（どう実装しているか）
- テストコードには What（何を保証しているか）
- コミットログには Why（なぜその変更が必要か）
- コードコメントには Why not（なぜ別の方法を取らなかったか）
