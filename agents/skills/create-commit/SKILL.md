# コミット作成

## 概要
変更内容を確認し、適切なコミットメッセージを作成してコミットを実行します。

## 手順
1. **変更内容の確認**
   - `git status`で変更されたファイルを確認
   - `git diff`で変更内容の詳細を確認
   - ステージングされていない変更がある場合は確認

2. **コミットメッセージの作成**
   - 変更内容を分析して適切なコミットメッセージを提案
   - コミットメッセージは以下の形式を推奨：
     - 1行目：変更の要約（50文字以内、動詞で始める）
     - 空行
     - 2行目以降：変更の詳細説明（必要に応じて）
   - 変更の種類に応じたプレフィックスを使用：
     - `feat:` 新機能
     - `fix:` バグ修正
     - `docs:` ドキュメント変更
     - `style:` コードスタイルの変更（動作に影響しない）
     - `refactor:` リファクタリング
     - `test:` テストの追加・変更
     - `chore:` ビルドプロセスやツールの変更
     - 参考：https://www.conventionalcommits.org/en/v1.0.0/


3. **コミットの実行**
   - 適切なファイルをステージング
   - 作成したコミットメッセージでコミットを実行
   - コミットが正常に完了したことを確認

## コミット前チェックリスト
- [ ] 変更内容が意図した通りか確認済み
- [ ] 不要なファイル（ログ、一時ファイルなど）が含まれていない
- [ ] 機密情報（パスワード、APIキーなど）が含まれていない
- [ ] コミットメッセージが変更内容を適切に説明している
- [ ] 関連するテストが通過している（可能な場合）
